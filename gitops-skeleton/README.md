# ${{ values.name }} — GitOps

Desired state for **${{ values.name }}** on OpenShift. Argo CD is the only thing that
applies it; nothing here is deployed by hand.

Generated by the `dotnet-api-azure-devops` Red Hat Developer Hub template alongside the
application repository: [${{ values.repo }}](${{ values.repoHttpUrl }}).

## Layout

```
chart/
├── Chart.yaml
├── values.yaml                             # shared defaults
├── values-dev.yaml                         # dev overrides   (image.tag written by CI)
├── values-prod.yaml                        # prod overrides  (image.tag written by CI)
├── .argocd-source-${{ values.name }}-dev.yaml
├── .argocd-source-${{ values.name }}-prod.yaml
└── templates/                              # Deployment, Service, Route, ServiceAccount
```

Both Argo CD applications point at the same `chart/` path. Argo CD reads
`.argocd-source-<application name>.yaml` from that path and merge-patches it over
`spec.source`, which is how each application ends up with a different `helm.valueFiles`
without duplicating the templates.

## Applications

| Environment | Argo CD application | Namespace | Values | Promoted by |
|---|---|---|---|---|
| dev | `${{ values.name }}-dev` | `${{ values.devNamespace }}` | `values-dev.yaml` | every build of `${{ values.defaultBranch }}` |
| prod | `${{ values.name }}-prod` | `${{ values.prodNamespace }}` | `values-prod.yaml` | manual *Promote to prod* pipeline stage |

Both applications sync automatically with `prune` and `selfHeal` on, so the gate for
production is the **manually triggered pipeline stage** that writes the tag into
`values-prod.yaml` — not an Argo CD sync button.

## How a change reaches the cluster

1. Commit to `${{ values.defaultBranch }}` in the application repo.
2. The pipeline builds `${{ values.imageReference }}:<BuildId>` and pushes it to Artifactory.
3. The *Deploy to dev* stage rewrites `image.tag` in `chart/values-dev.yaml` and pushes here.
4. Argo CD syncs `${{ values.name }}-dev`.
5. When you're ready, run the *Promote to prod* stage on that same pipeline run. It writes
   the identical tag into `chart/values-prod.yaml`, and Argo CD syncs `${{ values.name }}-prod`.

Because the promote stage reuses the build's own tag, prod can only ever receive an image
that already went through dev.

## One-time cluster bootstrap

The Argo CD applications are created with `CreateNamespace=false`, so the namespaces have to
exist first, and Argo CD needs permission to manage them.

```bash
# Namespaces
oc new-project ${{ values.devNamespace }}
oc new-project ${{ values.prodNamespace }}

# Let the OpenShift GitOps instance manage them
oc label namespace ${{ values.devNamespace }}  argocd.argoproj.io/managed-by=openshift-gitops
oc label namespace ${{ values.prodNamespace }} argocd.argoproj.io/managed-by=openshift-gitops
```

{% if values.imagePullSecret %}A pull secret named `${{ values.imagePullSecret }}` must exist in both namespaces:

```bash
for ns in ${{ values.devNamespace }} ${{ values.prodNamespace }}; do
  oc create secret docker-registry ${{ values.imagePullSecret }} \
    --docker-server=${{ values.containerRegistryHost }} \
    --docker-username='<artifactory user>' \
    --docker-password='<artifactory identity token>' \
    -n "$ns"
done
```
{% else %}If Artifactory requires credentials to pull, create a pull secret in both namespaces and
add it to `imagePullSecrets` in `chart/values.yaml`:

```bash
for ns in ${{ values.devNamespace }} ${{ values.prodNamespace }}; do
  oc create secret docker-registry artifactory-pull \
    --docker-server=${{ values.containerRegistryHost }} \
    --docker-username='<artifactory user>' \
    --docker-password='<artifactory identity token>' \
    -n "$ns"
done
```
{% endif %}
Argo CD also needs read access to **this** repository. Add it once under
*Settings → Repositories* in the Argo CD UI, or declaratively:

```bash
oc -n openshift-gitops create secret generic ${{ values.name }}-gitops-repo \
  --from-literal=type=git \
  --from-literal=url=${{ values.gitopsRepoHttpUrl }} \
  --from-literal=username='<azure devops user>' \
  --from-literal=password='<azure devops PAT with Code: Read>'
oc -n openshift-gitops label secret ${{ values.name }}-gitops-repo \
  argocd.argoproj.io/secret-type=repository
```

## Editing this repo

- **Environment differences** → `values-dev.yaml` / `values-prod.yaml`.
- **Everything else** → `values.yaml` and `templates/`, which both environments share.
- Leave the `tag:` line in each `values-<env>.yaml` as a single quoted scalar on its own
  line. CI asserts there is exactly one `tag:` key per file and fails loudly otherwise.

Render locally before pushing:

```bash
helm template ${{ values.name }}-dev  chart -f chart/values-dev.yaml
helm template ${{ values.name }}-prod chart -f chart/values-prod.yaml
```
